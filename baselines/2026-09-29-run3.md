## What this shows

- Two harmless commands containing the exact string `reset:permissions` **prompted**, and
  each box named `Bash(*reset:permissions*)`. Wrapping **that one harmless grep** in
  `sh -c '…'` did not stop it prompting. Nothing here speaks to `sh -c` in general.
- One harmless command containing `reset-permissions` — hyphen, not colon — **did not
  prompt**. That is one command's behaviour, **not a confirmed bypass**.

## What this does not show

- **Not that `node scripts/reset-permissions.js --dry-run` runs ungated.** That command
  was never run and is not covered by this probe. It carries its own `allow` entry, and
  what happens when it is invoked is untested.
- **Not that any real npm script is safe or unsafe.** None was run.
- **Not a universal matcher or precedence result.** Three commands, one session.
- **Not an auto-mode confirmation.** Auto mode was not separately checked; the only
  wording relied on is what the prompt boxes themselves say.

## Interpretation — Claude's, not verified

The `ask` patterns key on colon-separated npm script names, while the scripts they run are
hyphen-separated filenames. A string containing one does not contain the other. These three
observations are consistent with that, and with the possibility that an operation reachable
by both spellings is gated under one and not the other.

**That is a hypothesis about coverage, not a demonstrated bypass.** Confirming or refuting
it would need the real script invoked, which is exactly what this probe declined to do —
`reset:permissions` acts on macOS privacy permissions, and running a destructive command to
prove a prompt appears is a bad trade. If the gap matters, the fix is a decision about the
`ask` patterns, not another probe.

Two things that cannot be determined from this repo and are **not** claimed either way:
whether `reset-permissions.js` calls `tccutil` internally, which the global
`Bash(*tccutil*)` rule would not catch because it fires on a Bash command rather than a
call inside a Node process; and whether the `--dry-run` constraint on those `allow` entries
holds, given `ENVIRONMENT.md` records that argument-constrained patterns do not hold
reliably.
