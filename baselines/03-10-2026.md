## Why this session exists — corrected 2026-10-03

A blanket permission rule, `Bash(rtk proxy *)`, was found in the gitignored file
`~/.claude/.claude/settings.local.json`. On paper it pre-approved **any** command,
because that wrapper runs whatever it is handed. It was removed on 2026-09-30.

Then a harmless wrapped command that matches **no** allow rule and **no** ask rule
was run in a fresh session — and **no permission box appeared**. `rtk`'s own
`~/.local/share/rtk/hook-audit.log` confirms it ran verbatim, logged `skip:defer`,
so the hook did not rewrite it into some allowed form.

**The framing above omits auto mode, and that omission is the defect in this
investigation.** Confirmed 2026-10-03 from `/permissions`: **auto mode is active**,
with its own classifier (17 soft-allow, 72 soft-deny, 1 hard-deny, plus an
Environment block from user settings). The Check 3 permission box said so in as
many words: *"Ask rule `Bash(rtk proxy rm *)` overrides auto mode for this
command."*

So there are **three** outcomes for a command, not two:

1. An **ask** rule matches → box, every time. Overrides auto mode.
2. An **allow** rule matches → runs, no box.
3. **Neither matches** → the **auto-mode classifier** decides. It may allow
   silently. That is a decision being made, not a gate being skipped.

Whether auto mode was on during the 2026-09-30 observation is **not known** and
nothing readable records it. So that observation may have been auto mode working
as designed rather than evidence of a hole. **Do not write it up either way.**

**Still true, do not re-introduce as claims:** the checks do not prove the
`Bash(rtk proxy *)` removal closed a safety hole, and they do not prove unmatched
commands run unchecked in general.

### Check 3 — does a command that IS in the ask list still prompt? **DECISIVE**

Ask for this exact command, and nothing else:

```
rtk proxy rm --help
```

`--help` prints usage text only. **It deletes nothing.** It is covered by the ask
rule `Bash(rtk proxy rm *)`.

| Result | Meaning |
|---|---|
| **Box, naming a delete rule** | Ask rules fire correctly. |
| **No box** | **Far more serious.** It would mean the ask rules are not firing at all, and every conclusion in both documents becomes provisional. Stop and report — do not proceed to any fix. |

**Why this check is the decisive one — kept from the original, still true.**
Check 2 alone cannot tell "unmatched runs silently" apart from "permissions are not
working at all". Check 3 separates them: if a rule that definitely matches still
fires, the machinery works, and a silent unmatched command means something other
than breakage.

**Result 2026-10-03: box appeared, naming `Bash(rtk proxy rm *)`, and stating it
overrides auto mode.** Ask rules fire correctly, and they take precedence over the
classifier. **This check passed and is closed.** Command exited 64 with BSD `rm`'s
usage text; nothing was deleted.

**3 prompted, 56 did not.** The notable ones are `mv`, `cp -f`, `sed -i`, and the
`rtk err` / `rtk summary` / `rtk test` wrappers, which run arbitrary commands and

net for mistakes, not a lock against an attacker.
